# OmniInstall Project Principles

## Purpose

These principles define how decisions are made across the project.

## Principle 1: User Experience Over Technical Purity

If a technically elegant solution creates a worse user experience, the user experience should generally win.

## Principle 2: Reuse Existing Standards

Prefer integrating existing Linux standards over inventing new ones.

## Principle 3: Open Source First

The project should maximize transparency and community participation.

## Principle 4: Documentation Is A Feature

Undocumented functionality is incomplete functionality.

## Principle 5: Architecture Before Features

Short-term convenience must not compromise long-term maintainability.

## Principle 6: Safety Before Convenience

Users should never be surprised by destructive behavior.

## Principle 7: Beginner Friendly By Default

Advanced functionality is welcome, but the default path must remain approachable.

## Principle 8: Cross-Distribution Thinking

Features should be evaluated across the Linux ecosystem rather than for a single distribution.

## Principle 9: Transparency Without Overload

Technical detail should be available without overwhelming beginners.

## Principle 10: Sustainable Growth

The project should grow through stable foundations rather than uncontrolled feature expansion.
