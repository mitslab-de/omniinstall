# OmniInstall Vision

Version: 1.0 Draft  
Status: Foundation Document  
Owner: MITSLab  
Document Priority: Critical  
Last Updated: 2026-05-30

---

## 1. Vision Statement

OmniInstall exists to make Linux software installation simple for everyone.

The long-term vision is a Linux ecosystem where users no longer need to understand package managers, package formats, software repositories, or distribution-specific installation instructions in order to install applications safely.

A user should not think:

> Which package format do I need?

A user should think:

> I want this application.

OmniInstall should become the universal application layer above the fragmented Linux software ecosystem.

---

## 2. The Desired Future

In the desired future, a Linux user opens OmniInstall, searches for software, reads a clear human-friendly description, clicks install, and starts using the application.

The system decides how installation should happen.

The user remains informed but not burdened.

OmniInstall hides unnecessary complexity while preserving transparency for users who want to inspect details.

The experience should feel closer to a modern app store than a traditional package manager.

---

## 3. What OmniInstall Should Become

OmniInstall should become:

- a universal Linux application discovery layer
- a cross-distribution installation assistant
- a source resolver for package ecosystems
- a trusted application catalog
- a stack installer for complete workflows
- a bridge between beginner usability and Linux openness

It should not become a closed platform, a new distribution silo, or an attempt to replace every package manager.

---

## 4. The User Experience Vision

The normal user experience should be:

1. Search.
2. Select.
3. Install.
4. Use.

The advanced user experience should be:

1. Search.
2. Inspect available sources.
3. Review trust and compatibility information.
4. Choose or accept recommendation.
5. Install.

Both experiences must be supported without making the beginner experience feel technical.

---

## 5. The Platform Vision

OmniInstall should be designed as a platform, not only as a single application.

The platform should eventually include:

- core engine
- graphical desktop client
- command-line client
- application metadata catalog
- source resolver
- installation engine
- verification engine
- stack engine
- community contribution workflow
- documentation and governance system

Each part should be replaceable, testable, and documented.

---

## 6. Community Vision

OmniInstall should become a community-driven open-source project.

The community should be able to contribute:

- application metadata
- installation source mappings
- stack definitions
- documentation
- translations
- distribution compatibility reports
- bug reports
- safety reviews

The project should welcome Linux beginners, power users, developers, maintainers, designers, translators, educators, and organizations.

Community contribution should be structured enough to maintain trust, but accessible enough to encourage participation.

---

## 7. Open Source Vision

OmniInstall should be open source first.

The core should remain available, inspectable, forkable, and community-governed.

Commercial opportunities may exist around services, hosting, support, consulting, certification, and training, but the core user promise must not depend on proprietary lock-in.

Trust is a product feature.

Open source is part of that trust.

---

## 8. Long-Term Ecosystem Vision

OmniInstall can become the foundation for future MITSLab Linux-related projects.

In particular, OmniInstall may become a core application layer for a future OpenStore OS or other Linux distributions focused on usability.

The long-term ecosystem may include:

- universal Linux app catalog
- curated setup stacks
- education-focused software collections
- creator workstations
- developer workstations
- homelab server setups
- organization deployment profiles
- certified community recipes
- hosted registry services

The project should be designed so these future directions remain possible without compromising the MVP.

---

## 9. Ten-Year Vision

Within ten years, success would mean that a significant number of Linux users no longer search the web for distribution-specific installation commands.

Instead, they open OmniInstall.

A beginner should be able to install everyday software.

A creator should be able to install a complete streaming setup.

A developer should be able to install a reproducible workstation.

A school should be able to prepare Linux laptops with predictable software collections.

A community member should be able to contribute better metadata or installation mappings.

OmniInstall should become a practical answer to one of Linux desktop's most persistent usability problems.

---

## 10. Vision Guardrails

The vision must remain grounded.

OmniInstall should not try to solve every Linux problem at once.

The project should avoid:

- becoming a full operating system too early
- becoming an enterprise management suite before the user product works
- creating a new package format without necessity
- replacing package managers instead of orchestrating them
- prioritizing advanced users over normal users
- building monetization features before trust exists

The first promise must remain simple:

> Find software. Install software. No package-manager knowledge required.

---

## 11. Vision Summary

OmniInstall should become the universal Linux App Store layer: open, cross-distribution, source-aware, beginner-friendly, and powerful enough to grow into a broader software setup ecosystem.

It exists to make Linux easier without making Linux less open.
