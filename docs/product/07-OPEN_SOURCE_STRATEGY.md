# OmniInstall Open Source Strategy

## Mission

OmniInstall should remain an open-source-first project.

The core product should be inspectable, auditable, forkable, and community-improvable.

## Why Open Source

Trust is a product feature.

Users should be able to understand how software recommendations and installation decisions are made.

## Core Components

The following should remain open:

- Core Engine
- CLI
- GUI
- Specifications
- Documentation
- Metadata Schemas
- Governance Documents

## Community Participation

The project should actively encourage:

- code contributions
- documentation contributions
- translations
- application metadata improvements
- testing and validation

## Governance Goals

The project should avoid dependence on a single maintainer over the long term.

Documentation, architecture, and decision logs should make future stewardship possible.

## Commercial Alignment

Potential future commercial offerings must not weaken the open-source core.

Revenue opportunities should be built around services, support, hosting, certification, and consulting rather than artificial feature restrictions.

## Success

The open-source strategy succeeds when contributors trust the project and can meaningfully participate in its evolution.
